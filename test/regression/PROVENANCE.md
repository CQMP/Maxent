# Provenance of the references

**original numerics** of Maxent, before any modernization of the code.
The same information is stored as `provenance.*` attributes at the root of
every reference file.

## kk references (added 2026-09-24)

The three `kk_*` references were generated from commit `811b3c6` (kk writing
17 significant digits, otherwise unchanged; spline from GSL 2.8
`gsl_interp_cspline`), Release build (`-O3 -DNDEBUG -std=c++17`), AppleClang 21,
against ALPSCore `8d2ed3a9`. Two generations were bit-identical. The inputs are
made by `make_inputs.py`: Im G = -pi A of `u0_frequency` and Im Sigma of
`self_u1` (average spectra from these references), and the analytic Re G of a
unit Gaussian spectrum.

## GSL removed (step 2.2, 2026-09-24)

The references were generated with GSL (Legendre kernel integration, `kk`
spline). GSL has since been removed without changing any reference: the closed
form of the Legendre kernel reproduces the GSL kernels in `components.h5` to
3.3e-16 relative, all Legendre cases pass, and the new `kk` spline reproduces
the `kk` references bit for bit.

## legendre_convert reference (added 2026-09-24)

`legendre_convert_transform.h5` was generated from `modernize/step2` merge
commit `a57f150` using AppleClang 21, C++17, Boost 1.88, and ALPSCore
`560ae112`. The utility source was unchanged from the Boost implementation.
Its synthetic Gaussian-spectrum input has zero error bars, so the clock-seeded
bootstrap is deterministic; three consecutive generate-and-compare runs
passed.

## Bootstrap-error reference (added 2026-09-24)

`t_generate_err.h5` was generated from `modernize/step2.3c` after commit
`379b2f0`, using the Release build with AppleClang 21, libc++, C++17, and the
local ALPSCore installation. It uses the new default `SEED=0`; two independent
generations were identical. The reference includes `case.out.booterr.dat`.

## Time-bosonic references updated (B7b, 2026-09-24)

The `kernel_time_bosonic` datasets in `components.h5` and the
`t_kernel_time_bosonic.h5` reference were regenerated from
`modernize/step2.3c` after commit `46b5610`, using the Release build with
AppleClang 21 and libc++. All other component datasets are unchanged.
The component reference also adds a symmetric-grid time-bosonic kernel to
cover a negative first frequency and the exact ω=0 branch.

## Determinism

Two independent generations with the reference build were compared with
`compare.py --report`: all 1165 datasets (1157 numeric, 8 text) in 56 cases
were bit-identical.

## Variant builds (tolerance measurement)

(At the time, `dump_components` was built stand-alone against each Maxent
build tree; it is now a target of the main build.)

The tolerances in `tolerances.json` were set from the differences between the
reference build and these builds of the same baseline (see
[`MANIFEST.md`](MANIFEST.md) and [`REFERENCE_CHANGES.md`](REFERENCE_CHANGES.md)):

| Variant | Difference from the reference build |
|---|---|
| `-O0` | AppleClang, `-DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS_DEBUG="-O0 -g"` (appended after the forced `-O2`) |
| LAPACK | `-DUSE_LAPACK=1` (OpenBLAS 0.3.34 `dgesvd` instead of Eigen `JacobiSVD`), run with `OPENBLAS_NUM_THREADS=1` (multi-threaded OpenBLAS in 8 parallel runs oversubscribes the machine) |
| clang 22 | MacPorts `clang++-mp-22`, system libc++ |
| GCC 15 | MacPorts `g++-mp-15`, libstdc++, against an ALPSCore built with GCC 15 (MPI off). Needs `-include algorithm` (ALPSCore bug; fix proposed upstream in ALPSCore/ALPSCore#667) and a baseline copy without `-msse2` (B3). |

With the final tolerances, the LAPACK, clang 22 and GCC 15 builds pass all 56
cases, and the `-O0` build passes all cases except `legendre` (full size),
which did not finish within 30 minutes.

## Detection check

An older build of the same code that (a) lacks the B7 fix and (b) integrates
the Legendre kernel with Boost Gauss-Kronrod instead of GSL was compared
against the references:

* `t_kernel_time_bosonic` fails (spectra change by ~1e-5 relative, chi2 by 5e-4),
  and so does `kernel_time_bosonic` in `components.h5` (2.2e-3). No other
  case fails.
* The Legendre kernels agree with the GSL ones to 2e-16, so (b) is not a
  numerical change; the Legendre end-to-end cases stay within tolerance.
