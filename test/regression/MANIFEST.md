## Tolerances

Rules are matched in order against '<case>:<dataset>'; the first match applies. A dataset passes if max|a-b| <= atol + rtol * max|reference|. Values are about 10x the largest difference observed between the reference build and four variant builds of the same source (AppleClang -O0, LAPACK SVD, clang 22, GCC 15), rounded up; see PROVENANCE.md. The Legendre example is extremely ill-conditioned (minimal chi2 ~ 1e-17) and gets looser rules for its alpha probabilities and Ng.

| Pattern (case:dataset) | atol | rtol | Why |
|---|---|---|---|
| `^legendre_convert_transform:` | 1e-14 | 1e-12 | direct utility regression; allows only rounding-level variation |
| `:cli/` | 0 | 0 | command-line output and exit code must not change |
| `:log/scalars/(n_singular|max_it_warnings)$` | 0 | 0 | counts; identical in all variants |
| `:log/scalars/minimal_chi2$` | 1e-12 | 1e-06 | values below ~1e-12 are rounding noise (observed relative differences up to 1 at 1e-17) |
| `:log/scalars/posterior_probability$` | 1e-30 | 0.0002 | observed 2.1e-5; values below 1e-30 are rounding noise (Legendre: 1e-43) |
| `^legendre[^:]*:log/scalars/ng$` | 0 | 0.3 | Legendre: observed 2.9e-2 (GCC 15) |
| `:log/scalars/ng$` | 0 | 0.001 | observed 5.6e-5 |

## Known limitations

* The Legendre example is extremely ill-conditioned (minimal chi2 ~ 1e-17): rounding-level differences in the kernel change its alpha probabilities and Ng by up to 3e-3 and 3e-2 between compilers, so its end-to-end tolerances are loose. Kernel changes are caught by the Legendre kernel matrices in `components.h5`, compared at 1e-14. (Checks: Boost Gauss-Kronrod quadrature and, since step 2.2, the closed form used in maxent_kernel.cpp reproduce the GSL Legendre kernels of the references to 2e-16 and 3.3e-16.)
* `-O0` builds take more than 30 minutes for the full `legendre` case.
* `*.spex.dat`, `*.fits.dat` and `*.booterr.dat` are not compared (see README.md).
